# grant-radar — 사용 설명서

작성일 2026-06-05 · 프로젝트 grant-radar · 용도 처음 쓰는 사람을 위한 안내

## 무엇인가

정부지원사업 공고를 모아 신청자가 실제로 지원할 수 있는 공고를 가려내고, 그 위에 적합도·지원가치·신청서 초안을 제공하는 도구다. 공고 목록을 보여주는 디렉토리가 아니라, 사람 컨설턴트가 하던 판단을 대신한다.

## 쓰는 방법

세 가지 경로가 있다. 같은 백엔드에 붙는다.

| 경로 | 대상 | 접근 |
|---|---|---|
| 웹앱 | 사람 | `https://grant.sealcpa.com/` |
| MCP | AI 에이전트 | `https://grant.sealcpa.com/mcp` (Bearer 토큰) |
| REST | 스크립트 | `GET https://grant.sealcpa.com/api/grants` (토큰 불필요) |

### 웹앱

(1) 브라우저로 접속한다. 토큰 없이 실시간 공고가 뜬다.

(2) 왼쪽에 신청자 정보를 넣는다. 기업 유형, 하는 일(역량), 하려는 것(의도).

(3) 공고마다 자격 배지가 붙는다. `가능` 또는 `확인필요`다. 근거가 애매하면 `확인필요`로 두며, 멀쩡한 공고를 함부로 숨기지 않는다.

(4) 공고를 누르면 상세가 열린다. `fitPrompt`를 복사해 자신의 LLM(ChatGPT·Claude)에 넣으면 적합도·지원가치·준비물이 나온다.

### MCP

MCP를 지원하는 AI에 엔드포인트를 등록하면, 그 AI가 도구 3종을 직접 호출해 검색·열람·초안을 수행한다. 도구는 §도구 3종을 본다.

빠른 연결 확인은 다음과 같다.

```
npx @modelcontextprotocol/inspector
```

Transport를 Streamable HTTP로, URL을 `https://grant.sealcpa.com/mcp`로, 헤더에 `Authorization: Bearer <토큰>`을 넣어 연결한다.

### REST

읽기는 공개다. 토큰 없이 호출한다.

```bash
curl -G "https://grant.sealcpa.com/api/grants" \
  --data-urlencode "applicantType=중소기업" \
  --data-urlencode "capability=ESG 컨설팅"
```

## 도구 3종 (MCP)

| 도구 | 하는 일 |
|---|---|
| `match_grants` | 신청자 조건으로 자격 통과 공고 목록과 판정을 반환한다 |
| `get_grant` | 특정 공고의 본문·첨부·공고문 추출 텍스트를 반환한다 |
| `draft_application` | 공고 양식에 맞춘 신청서 초안 프롬프트를 반환한다 |

역할은 둘로 나뉜다.

(1) 자격 판정(`가능`·`확인필요`)은 서버가 코드로 계산해 그대로 넘긴다.

(2) 적합도·지원가치·초안의 판단과 글쓰기는 호출자 AI가 자신의 모델로 수행한다. 서버는 프롬프트만 제공한다. 따라서 서버는 LLM 인증키를 쓰지 않는다(BYO-LLM).

## 자격 판정

신청자의 대상(기업 유형)·업력·지역을 공고 요건과 맞춘다.

(1) 명확히 맞으면 `가능`, 명확히 다르면 `불가`로 목록에서 제외한다. 개인 대상 공고에 기업이 신청하는 경우가 `불가`다.

(2) 근거가 애매하면 `확인필요`로 남긴다. 거짓 `불가`로 멀쩡한 공고를 숨기는 것이 가장 큰 오류이므로 보수적으로 판정한다.

(3) 같은 뜻의 다른 표현은 같은 가족으로 인식한다. "스타트업"과 "창업벤처", "중소기업"과 "일반기업"이 그 예다.

## 초안 생성

`draft_application(공고 id, 신청자 정보)`를 호출하면 서버가 초안 프롬프트를 만든다. 실제 반환 예시는 다음과 같다.

```
아래 공고문/양식에 맞춰 사업계획서 초안을 작성하라.
[공고문/양식]   ← 그 공고의 실제 공고문(첨부 HWP 추출, 없으면 개요)
   …ESG경영체계 구축 지원…2천만원 규모 컨설팅 지원…
[신청자]        ← 넣어준 프로필
   해양 IoT 센서 3년차 중소기업, 매출 8억, 상시 12명, ESG 미구축
규칙: 공고문에 적힌 항목·평가기준에만 근거한다.
      정보가 없는 칸은 [채울 자리]로 둔다.
      없는 사실을 지어내지 않는다.
```

호출자 AI가 이 프롬프트를 실행하면 실제 초안 글이 나온다. 두 가지 원칙이 있다.

(1) 그 공고의 실제 공고문에 근거한다. 일반론이 아니라 해당 사업의 요건과 평가기준을 따른다.

(2) 모르는 칸은 지어내지 않고 `[채울 자리]`로 비워 둔다.

## 초안 수정

두 가지 방법이 있다.

(1) 대화로 고친다. 초안은 호출자 AI의 대화 안에 있다. "사업비 부분을 더 구체적으로", "`[채울 자리]`에 ESG 자가진단 결과를 넣어 다시"처럼 지시하면 같은 맥락에서 수정한다.

(2) 정보를 더 채워 다시 호출한다. 신청자 프로필을 자세히 넣고 `draft_application`을 재호출하면 `[채울 자리]`가 줄어든 초안이 나온다.

서버는 초안을 저장하거나 버전 관리하지 않는다. 초안은 호출자 대화에 머문다. 저장·이력 관리는 별도 기능으로 추가할 수 있다.

## 데이터

공식 4소스에서 받는다. K-Startup, 기업마당, 과학기술정보통신부, 중소벤처기업부다. 현재 약 150건이며 매일 자동 갱신한다. 마감이 지난 공고는 자동으로 숨기고, 여러 출처의 같은 공고는 하나로 합친다.
