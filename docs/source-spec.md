# 정부지원사업 공고 수집 — 출처 명세서

작성일 2026-06-04 · 프로젝트 grant-radar · 용도 수집기(크롤러·API 수집) 설계

## 목적

정부지원사업 공고를 모으는 수집기를 만들기 위해, 어떤 출처에서 어떤 방식으로 공고를 받을지를 정한다. 출처마다 공식 API인지 크롤링 대상인지, 정확한 엔드포인트와 인증, 응답 필드, 갱신과 난이도, 우선순위를 적어 더 조사 없이 구현에 들어갈 수 있게 한다. 기존 서비스들이 어떤 출처를 수집하는지는 출처 후보를 찾기 위한 정찰이며, 그 전수 목록을 부록에 둔다.

## 정의

(1) 공식 API — data.go.kr 또는 기관이 발급키 방식으로 제공하는 조회 인터페이스. 안정적이며 합법적이고 유지보수가 거의 없다.

(2) 크롤링 — 공식 API가 없는 기관의 게시판 HTML을 파싱하는 방식. 사이트 개편 시 깨진다.

(3) 검증 등급 — 확정(직접 받아 확인), 관측(서버 HTML에서 추출), 주장(회사 소개·미검증), 추정(패턴 추론).

## 일반 원칙

(1) 공식 API가 있는 출처는 크롤링하지 않는다. API를 먼저 깔고, 크롤링은 API가 없는 출처에만 쓴다.

(2) 출처는 소스 중립 스키마 하나로 흡수한다. 어댑터는 목록 조회와 단건 상세 두 가지만 구현하면 통합된다. 같은 출처에 나중에 API가 생기면 어댑터 내부만 교체하고 인터페이스는 유지한다.

(3) 목록만이 아니라 본문과 첨부까지 받는다. 사업계획서 보조의 입력이 공고 본문과 첨부이며, 첨부(HWP·PDF)에 평가배점과 사업비 비목이 들어 있다.

(4) 같은 공고가 여러 출처에 중복 게시된다. 출처, 공고번호, 제목과 마감일을 기준으로 중복을 제거한다.

(5) 출처를 늘리는 일은 끝없는 유지보수를 부른다. 가치가 낮은 긴 꼬리는 의도적으로 끊고, 제외한 출처는 기록으로 남긴다.

## 부록 A — 기존 서비스가 수집하는 출처 (전수)

출처 후보를 찾기 위해 조사한 기존 서비스다. 각 서비스가 실제로 어디를 수집하는지 확인된 범위까지 모두 나열한다.

### A.1 kfund.ai — 확정

출처는 K-Startup 공식 API 한 곳뿐이다. 서버리스 함수 `get-support-data`의 응답이 K-Startup API 스키마와 일치하며, 모든 상세 링크가 k-startup.go.kr로 향한다. 구조는 K-Startup API를 Firebase에 캐시해 Netlify 함수로 내보내는 방식이고 크롤링은 없다. 수익은 광고다.

### A.6 정찰 결론
